## 재현된 실패 (수정 전)

| 입력 | 수정 전 동작 |
|---|---|
| `--fps 30000` / `44100` (디코딩 샘플레이트 22050 초과) | 성공 종료. 1초 입력에 30000 프레임을 내보내지만 샘플이 부족해 약 7979개가 가짜 `[0,0,0,0,0,0,0]` 프레임 |
| `--fps 1e9` | 거대한 배열 할당으로 V8 OOM 크래시 (약 55초 후 rc=134) |
| `--fps 1e-9` | 성공 종료, 프레임 1개 (불변식 위반은 아님: 정수 0..255 7채널, 프레임 수 일치) → 수정하지 않음 |
| float WAV의 NaN / ±Infinity 샘플 | `clamp`가 비유한 값을 -1(최대 진폭)로 바꿔 무음 구간이 풀스케일로 분석됨 (1초 파일에서 비유한 샘플 122개 확인) |
| 오디오 스트림 없음/디코딩 결과 0샘플 (예: 영상만 있는 mp4 외 헤더만 있는 WAV) | 프레임 0개인 "정상" 프로필을 출력하고 종료 코드 0 |

## 수정 내용 (최소 변경)

- `--fps`: 기존 계약(유한한 양수 Number)을 유지하고 **22050 초과만 추가로 거부**한다. `0.05`, `1e1`, `0x10` 같은 이전에 유효했던 입력은 그대로 허용. 0, 음수, NaN/Infinity, 숫자가 아닌 값, 22050 초과는 `--fps ...` 메시지와 함께 종료 코드 1, 출력 없음. (0.1 미만은 불변식 위반이 재현되지 않아 제한하지 않음: `--fps 0.05`, `1e-9`는 프레임 1개의 유효한 프로필.)
- 디코딩 결과가 0샘플이면 오류(종료 코드 1, 출력 파일 생성 안 함).
- 비유한 PCM(NaN/±Infinity)은 무음(0)으로 처리. 유한 값 처리와 `clamp(-1,1)`은 그대로.
- `--help`의 `--fps` 설명에 지원 범위 추가.
- 기존 24/30/60/23.976 fps 처리 경로는 변경 없음.

## 지원 범위와 한계

- 지원 fps: 0 초과 22050 이하의 유한한 수(`0.05`, `1e1` 등 기존 입력 형식 포함). 11025 초과 구간은 프레임당 샘플이 1~2개라 의미가 거의 없다.
- 프레임 수는 `ceil(duration × fps)`이며 `duration`은 출력에서 소수 3자리로 반올림된다(매우 짧은 클립에서 `duration:0`, 프레임 1개 가능).
- 매우 긴 오디오(수 시간 단위)는 여전히 전체를 메모리에 올린다(스트리밍은 범위 밖). ffmpeg `maxBuffer` 512MB 한계도 그대로.
- 비유한 PCM은 오류가 아니라 무음으로 대체된다(경고 없음).
- 출력 파일은 완성된 JSON을 한 번에 쓰므로 분석 실패 시 만들어지지 않지만, 쓰기 중 디스크 오류까지 원자적으로 보장하지는 않는다.
